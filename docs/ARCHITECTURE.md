# Local architecture

`frontend/scripts/local.mjs` launches the existing Next foundation on `127.0.0.1:3210`. `middleware.ts` requires a loopback Host/local launcher and rejects cross-site Origin/fetch metadata. All old cloud/payment/login entrypoints were removed from the active app after verified baseline archival. Root and frontend Vercel ignore commands skip builds; `scripts/build.mjs` also rejects a Vercel environment. No hosted deployment is supported by this branch.

`components/workspace.tsx` provides five task groups sharing `app/globals.css` design tokens. Native labels, field constraints, visible keyboard focus, live error/status regions, semantic task navigation and responsive grids keep controls compact/readable. Advanced business fields, raw receipt metadata, legacy integration explanations and large source text are progressively disclosed. Previews use sandboxed iframes.

`lib/model.ts` is the strict, versioned shared schema: business profile, updates, captures, attempts and conversations. `lib/store.ts` serializes read-modify-write in the single server process. It validates, writes a temporary mode-0600 file, flushes and atomically renames. Edits/decisions use revision checks; network captures merge against latest workspace after fetching. No business save overwrites another tab silently. The local launcher enforces one writer per data directory with a PID lock and safely clears stale app locks; networked/multiuser use is outside scope. Invalid data is preserved and raises an explicit error. A JSON export/validated restore supports local backups.

`lib/templates.ts` adapts LocRaven contact/details/FAQ and schema patterns. It escapes HTML, script delimiters in JSON-LD, omits expired updates and includes approved references only. Hours are supplied text; the app never computes unsupported open-now status. Original six intent layouts are simplified into five factual views, with unsupported competitive/urgency/voice claims retired. HTML is standalone/inert; no local filesystem paths, secrets, tracking or remote assets are embedded.

`lib/capture.ts` adapts mirror-service extraction/version concepts. It resolves public IPs, pins DNS results in an Undici agent, blocks private/reserved addresses and unusual ports, follows at most five independently checked redirects, and bounds elapsed network time/response bytes. Cheerio extracts title/description/headings/text/links/JSON-LD after excluding executable/forms/remote content. Links/JSON-LD remain unverified source claims and are never executed or interpreted as instructions. The raw response hash/byte count/time/status are saved with extracted content; raw executable HTML is not stored. Empty/static-unsupported content fails honestly. Exact body hashes prevent duplicate pending/approved captures. Every changed version requires approval; approval supersedes only the previous approved version for the same source URL. Rejection leaves the approved version intact. Superseded/rejected history is removable locally after backup.

`lib/assistant.ts` preserves Castor's Dify streaming/stop request contract without Clerk/Supabase/Stripe. Only `CASTOR_ENABLE_DIFY=1` plus a legitimate project key enables sending. `lib/stream.ts` is the browser-safe SSE decoder. Conversation organization is local; successful, partial or failed responses have explicit persisted status. Workspace brief generation is deterministic and includes only saved facts/current updates/approved text. New local conversations, rename/delete and exports need no provider. Remote history import/title generation are not retained active. No Google route makes network calls; inactive status explains the original OAuth/account/token-only scope.

`app/api/[...path]/route.ts` exposes health/workspace, profile, updates, pages, source capture/review/removal/export, briefs, JSON-LD/backup/restore, conversations and optional chat/stop. JSON writes have a 16 MiB body limit, strict model validation and honest status errors. There is no cloud schema, auth/payment SDK, cron, deployment CLI, background snippet or customer write route.

See `CAPABILITIES.md` for exact provenance/disposition and durable archival locations. Generated build output, local data, captures and receipts stay outside source control.
